# 업무대화 일반의 저장 문맥

원문 목록 `general_business_english_literal_ko.json`의 200개 영어 문장을 하나씩 읽고 한국어 문맥을 작성했다. 각 항목의 `context`가 영구 저장된 문맥이며, 브라우저는 같은 내용을 담은 `business-contexts.js`를 사용한다. 단위 테스트가 두 자료의 문장 순서·내용·개수 일치를 검사한다. 시험 중 문맥을 생성하는 AI 호출은 없다.

## 작성·검토

각 문장의 화행(질문, 요청, 제안, 보고, 약속, 감사, 사과)을 확인하고, 소재와 의사소통 목적을 짧은 두 명사형 덩어리로 작성했다. 200개 모두 영어 원문과 대조해 상황·발언 목적·화자 관점·의미 일치를 검토했다. 번역에 접미사를 붙이지 않고 실제 발화 목적을 적었다. 자동 검사는 의미 검토를 대신하지 않는다.

- 화면이 보이는지, 자료가 보이는지, 상대방 화면을 공유해 달라는 요청을 구별했다(2, 3, 13).
- 의견을 받기, 발언에 동의하기, 아이디어를 긍정적으로 평가하기를 구별했다(30, 42, 43).
- 이해가 명확했는지 확인하기와 아직 불명확한 부분을 찾기를 구별했다(72, 73).
- 문제 확인, 원인 조사, 정확한 원인을 아직 모른다는 보고를 구별했다(162–164).
- 승인 필요 안내, 승인 요청, 승인 완료 보고, 승인 대기 보고를 구별했다(193–196).
- 41/120(확인 후 회신), 49/80(오늘 논의 종료), 55/59(회의 후 확인), 57/182(담당자 확인)처럼 목적이 사실상 같은 문장은 인위적인 배경 차이를 만들지 않았다.

검토 대상 200개, 작성 완료 200개, 누락 0개. 의미가 같은 확인 후 회신 표현은 같은 문맥을 사용했다. 전체 목록은 [200개 변경 문맥](business-contexts-200.md)에 기록했다.

## 사용자 데이터 보존

기존 챕터명 `영어업무(일반)`, `업무대화 일반`, `업무대화(일반)`에 속하고 영어 원문이 정확히 일치하는 카드만 대상으로 한다. 앱 초기화 시 문맥이 없는 카드에 저장 문맥을 채워 기존 카드 저장소에 저장한다. 기존 ID, 번역, 영어 정답, SRS 단계·일정, 오답 횟수, 북마크 및 부가 필드는 유지한다. 이전 배포 기본 문맥과 정확히 일치하는 문자열만 새 기본값으로 갱신한다. 그 외 사용자가 작성한 문맥과 의도적으로 비운 문자열은 덮어쓰지 않는다. 이전 기본값과 완전히 같은 사용자 입력은 별도 수정 이력이 없어 구분할 수 없다. 새로운 카드나 챕터를 자동으로 만들지 않는다.

사용자 기기/동기화 데이터는 해당 앱이 열릴 때 이 절차가 적용된다. 저장소의 200문장 목록에 없는 사용자 추가 문장에는 임의 문맥을 생성하지 않는다.

## 사용 및 저장 경로

학습 화면의 ‘문제 유형’에서 ‘문맥 시험’을 고른다. 문맥이 저장된 출제 대상만 기존 SRS·순서·개수 규칙으로 선택한다. 기존 번역 시험이 기본값이다. 연습 모드는 기존과 같이 복습 일정을 바꾸지 않는다.

문맥 시험에서는 제출 전 번역과 영어 정답을 표시하지 않는다. 현재 문장의 편집·질문·이력은 제출 전 잠그고 최초 출제와 재출제 2단계에서는 문맥만 제시하고, 재출제 1단계에서는 번역 시험과 같은 `buildAnswerSilhouette` 함수로 만든 영어 실루엣을 함께 표시한다. 기존 2단계 재출제·판정·SRS 처리 경로는 유지한다. 새로고침 복원에는 문맥 시험 여부도 저장한다.

‘전체 문장’에서 문장을 선택하고 기존 ‘편집’ 버튼을 누르면 ‘문맥’을 수정할 수 있다. 기존 변경 확인/적용 절차 후 카드의 `context`에 저장되며 다음 문맥 시험에 반영된다. 카드 관리의 목록에도 문맥 → 한국어 → 영어를 표시하고 바로 편집할 수 있다. 직접 추가와 학습 완료 후 편집도 같은 순서로 문맥을 입력·수정한다. 문맥이 없는 카드는 `문맥 미등록`으로 표시한다. 검색은 기존 한국어·영어와 문맥을 모두 지원한다. 기존 카드 백업·복원·동기화가 전체 카드 객체를 보관하므로 문맥도 함께 보관된다.

Chromium 검사는 200개 마이그레이션, 원래 기록 보존, 편집 확인/적용, 실제 다운로드 백업과 파일 업로드 복원, 사용자 문맥·빈 문맥 보존, 시험 재시작, 제출 전 정답 접근 차단, 2단계 재출제, SRS, 번역 시험을 확인한다. 네트워크 요청을 감시하며 동기화/AI Worker에 접근하지 않는 격리된 데이터로 실행한다.

문맥 시험은 기존 재출제 반복과 건너뛰기 처리를 공유한다. 1단계에서 넘어가면 같은 문제의 2단계로 즉시 이동하고, 2단계에서 넘어간 ID만 모든 대기열에서 제거하며 복원 시에도 제외한다. Chromium 검사에 1·2단계의 마지막 카드 건너뛰기, 여러 카드에서 반복·건너뛰기·오래된 대기열 복원, 데스크톱·모바일의 표시 순서·문맥 검색·추가·편집·빈 문맥 보존을 포함한다.

전체 문장 탭은 문맥·한국어·영어를 각각 독립 토글한다. 문맥 OFF는 영역 전체를 접으며, 한국어·영어의 기존 투명 처리 방식은 유지한다. 세 토글은 기존 방식대로 현재 앱 실행 중에만 유지하고 새로고침하면 기본 ON으로 돌아온다. 설정·백업·동기화에 별도 토글 값을 추가하거나 기존 값을 변경하지 않는다. 문맥 표시 여부는 카드 관리 화면이나 시험 출제에 영향을 주지 않는다.

## 저장된 구버전 문맥 갱신 (v75)

실제 출제·전체 문장·카드 관리는 `localStorage.srs_cards_v2.cards[].context`를 공통으로 읽는다. 원본 JSON은 검토 자료이고 런타임 로더가 아니다. `business-contexts.js`가 앱 초기화 시 알려진 기본값만 갱신하며 `business-priorities.js`는 분류·식별 자료다. IndexedDB 카드 저장 경로는 없다. 학습 체크포인트는 카드 ID를 저장하고 복원 시 같은 카드 객체를 참조한다. 동기화는 카드 객체를 localStorage에 적용한 뒤 앱을 로드하고, 백업 복원도 저장 후 다시 로드하므로 같은 마이그레이션을 통과한다.

저장된 기본 문맥은 `CardOverrides.defaults`에서 변경 이력에 `template-default-migration`을 추가한 뒤 갱신한다. 따라서 옛 기본 문맥 이력이 다음 동기화 때 값을 되돌리지 않는다. `When do we need to finish this?`의 알려진 구버전 문맥과 실제 완전 스냅샷에서 확인된 여섯 구버전 문맥을 정확히 등록했다. 앱에서 직접 편집한 문맥은 `contextUserEdited: true`와 편집 이력으로 보호하고, 구버전의 알려지지 않은 사용자 문맥은 자동 변경하지 않는다. 알려진 이전 기본 번역 `ko_before`도 사용자 편집 이력이 없을 때만 최신 기본 번역으로 옮긴다. 전체 과정에서 카드 ID, SRS, 오답 기록, 학습 통계, 우선순위 및 테스트 상태를 변경하지 않는다.

출처 표시가 없는 임의 문맥을 자동 생성값과 사용자 편집값으로 완전히 구분할 수는 없다. 따라서 영어별 이전 기본값 200개와 실제 확인된 추가 기본값만 교체한다. `하려고 할 때` 같은 문장 형태만으로 사용자 데이터를 덮어쓰지 않는다. 알려지지 않은 다른 자동 생성 문구가 있는 경우에는 그 정확한 영어·문맥 쌍을 교체 목록에 추가해야 한다. 이전 기본값과 같은 문구로 이미 편집했고 편집 표시도 없는 경우 역시 사후 구별할 수 없다.

Service Worker는 앱 파일을 네트워크 우선으로 제공한다. v75는 자바스크립트 자산에 같은 버전 URL을 사용하고 그 URL을 미리 캐시하며, 활성화 시 이전 **앱 자산 캐시**만 교체한다. 카드 localStorage와 학습 체크포인트는 삭제하지 않는다. 브라우저 테스트는 저장된 200개 구버전 카드, 보고된 문구, 전 화면 표시, 학습 중 재시작, 모의 완전 동기화 스냅샷, 사용자 편집값과 빈 값, 실제 Service Worker와 구버전 자산 캐시를 검사한다. 테스트의 클라우드 응답은 격리된 모의 응답이며 사용자 계정의 Worker 데이터를 읽거나 쓰지 않는다.

## Codex용 앱 데이터 읽기 설정

앱 카드와 학습 데이터는 `localStorage.srs_cards_v2` 등에 저장되며, 별도 IndexedDB 카드 저장소는 없다. 기존 Worker는 동기화 코드로 인증하는 `get`/`set` API를 제공한다. 이 스크립트는 기존 프로토콜의 `get`만 호출하며, 완전성 메타데이터가 없는 스냅샷은 최신 데이터로 취급하지 않는다. Worker 데이터가 누락되거나 충돌이 있으면 템플릿 반영을 중단한다.

Linux/macOS 터미널에서 최초 한 번 실행한다.

```sh
npm run sync:app-templates:setup
```

프롬프트에 앱에서 사용 중인 동기화 코드를 입력한다. 터미널 입력은 표시하지 않으며, 코드는 저장소 밖의 `~/.config/memory-app/worker-sync.json`에 권한 `0600`으로 저장된다. 전체 카드 스냅샷도 같은 디렉터리에 `latest-app-snapshot.json`으로 권한 `0600`을 적용해 저장한다. 설정 파일은 Git에 포함하지 않는다.

이후 읽기 및 차이 확인은 다음과 같다.

```sh
npm run sync:app-templates -- --dry-run
```

출력에는 카드 수, 편집·삭제·차이·충돌 개수만 포함되며 카드 문구와 인증 코드는 표시하지 않는다. 이 명령은 Worker `get` 한 번, `set` 0회, GitHub 쓰기 0회로 실행한다. 충돌은 종료 코드 2, 설정·인증·네트워크 오류는 종료 코드 1이다.

실제 앱 스냅샷(카드 390개, 충돌 0개)을 읽어 템플릿 차이를 확인했다. 차이 288건은 템플릿 키가 없는 다른 챕터 카드 191건과 키가 연결된 일반업무 카드 97건으로 나뉜다. 연결된 카드에서 앱 이력과 현재 값을 대조해 영어 1건, 한국어 97건의 수정을 확인했다. 한국어 27건은 저장된 구버전 기본 번역(`ko_before`)과 일치하고 사용자 편집 이력이 없어 최신 기본 번역을 유지했다. 일반업무 템플릿 200개 중 한 키는 앱 스냅샷에 없고 삭제 이력도 없어 기본 템플릿으로 보존했다.

Codex 실행 환경과 별도의 Linux 터미널은 네트워크 연결이 다를 수 있다. 현재 명령은 사용자의 비공개 설정 코드로 Worker `get`을 실행해 최신 스냅샷을 저장하고 차이만 요약한다. 저장소 템플릿은 스냅샷에 포함된 키·이력·기준선을 검증한 뒤 변경한다. Cloudflare Worker 코드는 수정하지 않는다.
