# 재출제 포기 후 재등장 방지

## 확인한 경로

- `skipRetestCard()`의 일반 클릭은 기존에도 `retestUnresolvedIds`와 `retestQueue`를 제거했다. 그러나 포기 사실 자체를 보관하지 않았고 `retestCandidateIds` 등 다른 출제 목록에는 ID가 남았다. 과거 큐가 재사용되는 경우 이를 거부할 최종 상태가 없었다.
- 문서 전역 Enter 핸들러는 `skipRetestBtn`에 포커스가 있어도 표시 중인 `nextBtn`을 우선 처리했다. 따라서 포기 대신 `confirmWrongAnswer()`가 실행되어 현재 ID를 `retestQueue` 뒤에 다시 등록했다. 1·2단계 모두 수정 전 Chromium에서 반복을 재현했다.
- 일반 모바일 탭만으로 반복되는 상황은 정상적인 최신 큐에서는 재현하지 못했다. 대신 모바일 탭 후 포기 ID가 후보 목록에 남는 것을 확인했고, 오래된 큐와 현재 ID가 저장 상태에 재유입된 상황을 명시적으로 재현해 방어했다. 사용자 기기의 개별 발생 경로까지 단정하지 않는다.
- 큐에는 별도 고정 인덱스가 없다. `loadNext()`는 `shift()`로 다음 ID를 꺼내며, 비어 있으면 미해결 ID 목록으로 큐를 재생성한다. 따라서 두 배열만 비우는 것보다 모든 큐와 재생성 원천에서 포기 ID를 제외하는 것이 필요하다.

## 수정

- 세션 복원 기록에 로컬 전용 `retestAbandonedIds`를 추가했다. 새 테스트 시작 시에만 초기화하며, 이전 형식의 복원 기록은 빈 배열로 읽는다.
- `abandonRetestId()`와 `pruneAbandonedRetests()`가 현재 테스트의 `sessionQueue`, `retryQueue`, `retestCandidateIds`, `retestQueue`, `retestUnresolvedIds` 및 `retestStages`에서 대상 ID의 모든 항목을 제거한다. 다른 ID의 순서는 보존한다.
- 다음 문제 선택 전, 저장된 세션 복원 시, 일반 재시도 및 단계 승급 후 재등록 경로에 제외 검사를 적용했다. 오래된 현재 문제가 포기된 ID여도 다시 채점하지 않고 다음 유효 문제로 이동한다.
- 포기 동작은 이전 자동 전환 토큰을 무효화하고, 단계 대기 동작을 초기화한 뒤 같은 이벤트 처리 내에서 다음 문제 또는 정상 완료 화면으로 이동한다. 중복 클릭도 재처리되지 않는다.
- 건너뛰기 버튼의 Enter를 전용 핸들러로 전달하고 기본 동작을 취소한다. 결과 화면의 지연 포커스도 사용자가 건너뛰기/수동 정답 버튼을 선택했다면 이를 빼앗지 않는다.

## 보존 범위와 검증

채점·철자 판정 함수와 일반 `다음 문제`의 기존 재시도 규칙은 변경하지 않았다. 포기 처리는 세션 상태만 바꾸고 최초 오답 기록, `ngCount`, SRS 및 설정을 추가로 저장하지 않는다. 동기화·백업 데이터 형식과 Cloudflare Worker도 변경하지 않았다.

단위 테스트는 중복 ID 제거, 큐 순서 보존, 최초 오답/완료 목록 보존 및 오래된 항목의 재유입 차단을 검증한다. Chromium 회귀 테스트는 모바일 터치·Enter 각각의 1·2단계 포기, 마지막 문제 정상 완료, 연속 포기, 중복 클릭, 새로고침, 오래된 현재 ID/큐를 넣은 뒤 복원, SRS/오답/설정 원문 동일성을 검증한다. 기존 일반 재시도와 철자 판정 회귀 테스트도 함께 실행한다.

로컬 최종 결과: `npm test` 통과, 단위 테스트 및 Chromium 34개 모두 통과.
